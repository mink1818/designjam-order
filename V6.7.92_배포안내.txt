DESIGN SOCKS V6.7.92 배포 안내

[수정 원인]
관리자 주문수정에서 상품목록 품번은 저장되지만 ERP inventory_items 재고와 연결되지 않은 품번이 저장될 수 있었습니다.
이 상태에서는 피킹 화면에 "ERP 재고 미등록"이 표시되고 최종 피킹 검증이 중단될 수 있었습니다.

[수정 내용]
1. 주문수정 저장 전에 ERP 재고 연결을 화면과 서버에서 모두 검사합니다.
2. S-4701 / 4701처럼 출고지 접두어 표기만 다른 품번은 동일 품번으로 연결합니다.
3. 실제 미등록 품번은 기존 주문을 변경하지 않고 저장 단계에서 안내 후 중단합니다.
4. 기존에 접두어 차이로 재고 연결이 끊긴 주문도 피킹할 수 있도록 피킹 재고 조회를 보강합니다.
5. 주문수정 저장 후 재고 캐시를 즉시 갱신합니다.

[적용 순서 - 중요]
1. Supabase SQL Editor에서 아래 파일 전체를 한 번 실행합니다.
   SQL/V6.7.92-ORDER-EDIT-INVENTORY-PICKING-GUARD.sql

2. 프로젝트 전체를 배포합니다.
   git add .
   git commit -m "release v6.7.92 fix order edit inventory picking link"
   git push origin main

3. 배포 완료 후 브라우저에서 Ctrl+F5로 새로고침합니다.

[기존 S-4701 주문]
SQL과 배포 적용 후 다시 피킹해보세요. 접두어 차이 문제라면 바로 정상 연결됩니다.
그래도 "ERP 재고 미등록"이면 ERP 재고센터에서 "상품 품번 동기화"를 한 번 실행하고 4701의 재고수량을 확인한 뒤 피킹하세요.
재고수량은 임의 생성하거나 변경하지 않습니다.

[기존 데이터 영향]
기존 주문, 주문금액, 재고수량을 일괄 수정하지 않습니다.
SQL은 저장/피킹 함수만 안전하게 교체하며 오류 발생 시 전체 작업이 롤백됩니다.
