DESIGN SOCKS V6.7.93 배포 안내

[확인된 원인]
거래처 단가표에 같은 품번이 6061 / S-6061처럼 서로 다른 표기로 함께 존재할 경우,
주문수정 화면에서 나중에 읽힌 행이 앞의 단가를 덮어써 50원 차이가 재발할 수 있었습니다.

[수정 내용]
1. 거래처명 전용단가를 ID 단가보다 항상 우선합니다.
2. 같은 품번 표기가 여러 개면 접두어 없는 정확한 품번을 우선합니다.
3. 화면과 서버가 동일한 단가 선택 규칙을 사용합니다.
4. 관리자 대신주문 및 기존 대신주문의 주문수정 추가품번에 모두 적용합니다.
5. 모든 거래처·모든 품번에 동일하게 적용합니다.
6. 기준 품번 없이 서로 다른 단가가 충돌하면 임의 저장하지 않고 오류로 중단합니다.
7. 과거 주문금액과 기존 단가표 데이터는 변경하지 않습니다.

[적용 순서]
1. Supabase SQL Editor에서 아래 SQL 전체 실행
   SQL/V6.7.93-CUSTOMER-PRICE-CANONICAL-ITEM-FIX.sql

2. 프로젝트 전체 배포
   git add .
   git commit -m "release v6.7.93 fix proxy edit customer price selection"
   git push origin main

3. 배포 완료 후 브라우저에서 Ctrl+F5

[부산마야 확인]
기존 주문수정 화면을 닫았다가 다시 열고 6061, 6062, 6064를 추가하면
부산마야 거래처명 전용단가가 자동으로 표시되고 서버 저장 시 같은 값으로 다시 검증됩니다.

이미 잘못 저장된 주문가격은 과거 주문 보호를 위해 자동 변경하지 않습니다.
해당 주문은 수정 화면에서 6061, 6062, 6064를 다시 선택하여 저장해주세요.

[전체 거래처 단가 충돌 점검]
SQL 적용 후 SQL Editor에서 아래 조회를 실행할 수 있습니다.
select * from public.audit_customer_price_conflicts();

결과가 0행이면 동일 품번의 서로 다른 전용단가 충돌이 없습니다.
결과가 나오더라도 주문을 임의 금액으로 저장하지 않도록 서버에서 차단됩니다.
